## 所有卡片共用的硬规则

- 分支：从 `dev` 拉分支，命名 `feat/<card-id>-<slug>`、`fix/<slug>` 或 `contract/<slug>`（C10.1）。
- 提交：中文写清「改了什么及为什么」，正文末尾带 `Contract:` 与 `Card:` 两行；必须带 `--no-gpg-sign`；禁止 `--no-verify`（C10.2）。
- 收工门禁：`pnpm check:all` 9 步全绿，不通过禁止收工（C9.1）。
- `src/bindings/types.ts` 是生成物，只能由 `pnpm gen:bindings` 产生，生成后一并提交。
- 「Write set」上限 8 个代码文件；测试文件不计入上限。
- 需要扩大「Write set」时：先停下，说明原因，由用户确认后再动。
- 涉及原生窗口 / 热键 / 输入法 / 侧栏的卡片，由用户在真实 macOS 上完成卡内「人工点验」。

## 用户已确认的口径（施工时不要再问）

- 左侧栏导航最终顺序：`目录｜标签｜最近｜相关文档｜大纲`。「收件箱」标签页与 V4 遗留的「工作区」标签页都删除。

- 顶部横栏整体删除：「视觉基线预览」在设置里已有；「退出侧栏辅助」「拉出导航」移到编辑器区右上角。
- 标签右键「删除」子菜单 = 删除文件到废纸篓。
- 配置备份的文件选择用官方 `tauri-plugin-dialog`。
- 废弃的全局工作区模型可以一并删除，但必须放在最后、不引起后续任务错乱（第 30 张，可选）。
